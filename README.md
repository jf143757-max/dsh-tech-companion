# Tech Companion / 技术学习搭子

在用 AI 完成任务的过程中，顺手学会更准确地理解和表达技术问题。

**知其然，更要知其所以然。** 核心理念是干中学：不另开一门课，就在你正在做的任务里学。

## 为什么做这个项目

越用 AI，越不敢承认自己不懂。这不是你笨，而是现在的大模型只给答案，答得又快又满，从不补一句为什么。任务做完了，概念还是糊的。等离开 AI 对话，向群友请教、交流方案或一起解决问题时，如果概念和用词有偏差，彼此就可能理解成不同的事情。

这个项目想做一个陪伴：在不打断任务的前提下，遇到不准确或不够规范的技术用词时，温和地讲清楚更准确的说法、背后的原因，并给一句能直接跟别人说的话。让我们一边享受 AI 带来的乐趣，一边动手、一边学习，逐渐建立知识和沟通能力。

我们相信学习不需要先说对才能开始。口语化表达、合理的类比和正在探索的想法都值得被理解：即使口语说法本身没错，也可以顺带介绍更具体的术语，但不应把它说成错误。

## 它分三层

| 能力 | 需要什么 | 装上就有？ |
| --- | --- | --- |
| 做完任务后，以「吱吱老师提醒你：」给一张小卡：知识点、为什么、能这样说 | 只是一段静态指导，跟着现有对话走 | 是 |
| 把每次提醒记成知识点卡；你说「今天汇总」就生成当天汇总和到期快问 | 学习账本：你同意记录后，在本机写一个 JSON 文件 | 第一次提醒时问你一次，你说「好」才开始 |
| 每天固定时间自动发汇总 | 宿主的定时器：Harness 的定时任务，或 Hermes gateway 里的 cron | **否**。要你同意后由助手创建，宿主在运行时才会触发 |

静态指导本身做不到定时推送和记账；后两层是这次补上的轻量组件（零依赖 Node.js 脚本 + Harness 工具），定时则交给宿主。没有定时器的环境，就在你说「今天汇总」时生成，不会假装「装上就每天推」。

## 提醒长什么样

以下是模拟对话，展示期望的提醒方式。实际回复会随模型和上下文变化，插件不能保证模型每次都照做。

### 1. 信息错误：理解有偏差

> 你：我家是千兆宽带，帮我查一下为什么下载速度不到 1000 MB/s。
>
> 助手：我先帮你检查实际下载速度和连接情况。……
>
> 吱吱老师提醒你：千兆宽带通常指 1000 Mbps（兆比特每秒），理论速度约 125 MB/s，不是 1000 MB/s。
> 为什么：1 字节等于 8 比特，1000 ÷ 8 = 125。
> 能这样说：“我的宽带是千兆的，想看看下载速度是否正常。”

### 2. 表达不够具体：意思对，但可以说得更清楚

> 你：帮我在网页上建个模型，可以旋转查看。
>
> 助手：我先了解你想展示的模型和交互方式，再安排实现。……
>
> 吱吱老师提醒你：“网页建模”能让人理解你的大致想法；如果你打算用 Three.js，可以说得更具体。
> 为什么：网页 3D 有好几种做法，点名工具能让对方直接给出可用的方案。
> 能这样说：“帮我用 Three.js 做一个可旋转查看的网页 3D 模型。”

“网页建模”不一定说错；如果还没决定用什么工具，助手不应替用户假定使用 Three.js。

### 3. 概念混淆：把两个相近的东西当成一回事

> 你：把 Mac Studio 的屏幕关掉，让它睡眠后继续下载文件。
>
> 助手：我会先检查电源设置，确认如何保持下载运行。……
>
> 吱吱老师提醒你：关闭屏幕和系统睡眠是两回事。屏幕关闭时电脑可以继续工作；进入系统睡眠后，下载通常会暂停。
> 为什么：关屏只停掉画面输出，睡眠会挂起进程和网络连接。
> 能这样说：“关掉屏幕，但让电脑保持运行。”

### 4. 信息缺失：任务能理解，但需要补充条件

> 你：帮我装一个能在我显卡上运行的大模型。
>
> 助手：我先确认你的显卡型号、显存和用途，再选择适合的模型。……
>
> 吱吱老师提醒你：选模型时，显卡型号和显存大小都会影响选择。
> 为什么：模型要整个放进显存才跑得顺，显存不够就只能选更小的模型或量化版本。
> 能这样说：“我的显卡型号是……，显存是……，想用模型来……”

信息缺失不代表说错了；补充这些条件有助于别人更快理解需求。

### 5. 忽略前提：方案可能成立，但还需要确认

> 你：照片已经同步到云端了，帮我把电脑上的全部删掉，给电脑腾空间。
>
> 吱吱老师提醒你：有些云同步服务会把删除操作同步到其他设备和云端。建议先确认服务的删除规则，并检查有没有独立备份，再决定怎么清理。
>
> 助手：我先确认使用的是哪种同步服务和清理方式。

可能造成伤害、数据丢失或不可逆后果时，提醒在相关操作之前给出。没有术语可补充时不强行提醒。

## 知识点卡片

每次提醒都会落到一张卡上（需要你同意记录）。卡片只有 7 个内容字段：

| 字段 | 说明 |
| --- | --- |
| 日期 | 第一次遇到的日子，也是复习的第 0 天 |
| 原话 | 可选；你自己说过的一小句（最多 80 字）。你没说过就不填，不编造 |
| 知识点 | 更准确的说法 |
| 为什么是这样 | 背后的原因 |
| 今天在哪个任务里遇到的 | 几个字的任务名，不是任务内容 |
| 能这样说 | 一句能直接跟别人说的话 |
| 易错点 | 可选；容易错在哪 |

此外只有复习排期用的数据（影响程度、复习阶段、下次复习日、上次回答）。**不记聊天全文**：工具只接受上面这些字段，其他内容（对话、文件、密钥、姓名）一律丢弃，每个字段有长度上限。

- 存在哪：`~/.tech-companion/ledger.json`（可用环境变量 `TECH_COMPANION_HOME` 改位置）。只在本机，不联网，不额外调用模型。
- 第一次：助手在第一次提醒后给你看一份默认套餐，你回一句「好」才开始记；不同意就说不要，以后不再问。
- 关闭：随时说「关闭记录」，之后不再写新卡（已有的卡照常复习）；「恢复记录」重新开始。
- 清空：删除上面那个文件夹，或运行 `node skills/tech-companion/scripts/companion.mjs clear --yes`。

## 每日汇总

把散的提醒变成能复盘的账本，让学习有指向性。第一次用时每一项都有默认值，回一句「好」就全部接受；想改哪项，说一句话就行，不用回答一串选择题，也不用进设置页。

| 项目 | 默认 | 一句话就能改 |
| --- | --- | --- |
| 时间 | 每天 21:00 | 「改成 22 点」「改到晚上 9 点半」 |
| 频率 | 有新点或有到期复习点才发；什么都没有就不发空汇总 | 「只在我说的时候汇总」「暂停汇总」「恢复定时汇总」 |
| 渠道 | 就在这个对话里，不另开地方 | 「以后发到 Telegram」（需要宿主支持该渠道） |
| 数量 | 新点最多 3 个，按对任务的影响排序；复习快问：定期模式最多 3 个，每天模式最多 5 个 | 「以后只发 1 个」「复习最多 2 个」 |
| 格式 | 每个新点：知识点、为什么、任务场景、能这样说；最后 1 道复盘小问题，点出当天几个点的共性 | 「不要复盘题」「加上易错点」 |
| 记录 | 只记知识点卡片，不记全文 | 「关闭记录」「恢复记录」 |
| 复习模式 | 定期复习 | 「改成每天复习」「改回定期复习」 |

关于「频率」：默认是“有新点**或到期点**才发”。如果只在有新点时才发，安静的日子里到期的旧点就永远等不到复习，间隔复习就失效了；所以“空日”的定义是既没有新点、也没有到期点，这样的日子不发。

汇总长这样（复盘小问题由模型改写成真正点出共性的一题；零模型调用的 Hermes 模式下是模板题）：

```
吱吱老师今日汇总 · 2026-11-03

今天的新点（2）
1. 知识点：千兆宽带是 1000 Mbps（兆比特每秒），理论上约 125 MB/s，不是 1000 MB/s
   为什么：1 字节（B）= 8 比特（b），1000 ÷ 8 = 125
   任务场景：排查家里下载速度
   能这样说：我家是千兆宽带，理论下载上限约 125 MB/s，想看看现在的速度是否正常。
2. ……

复习快问（1）——想起来回「c3 记得」，想不起来回「c3 忘了」，不扣分
· [c3] 你当时说「GitHub 这个应用商店」——现在换你跟别人讲，会怎么说？

复盘小问题：……

—— 快问参考答案（先想一想再看）——
[c3] 这个工具的源码在 GitHub 上，我去看看 Releases 里有没有安装包。
```

同一天已经汇总过的点不会再出现；新点超过上限时，没放进去的点会在你再说「今天汇总」时出现，并照常进入复习。

## 间隔复习

先说准概念：**遗忘曲线**是艾宾浩斯描述“记忆随时间衰减”的一条曲线，它不是算法，也不是对你大脑的测量。真正安排复习时间的是**间隔重复**这类算法（如 SM-2、Leitner 盒子），根据你答对答错调整间隔。这里用的是最简单的一种：固定台阶、类似 Leitner。

- 每张卡第一次出现算第 0 天，按时复习的话在第 +1、+3、+7、+15、+30 天再出现。
- 回「记得」：上到下一个更长的台阶（间隔从实际复习那天算起）；在 +30 那一步还记得，就算掌握，不再安排。
- 回「忘了」：回到 +1 天重新排，没有别的惩罚，不是考试。
- 没回答：汇总里你已经看过题和答案，算“看过一次”，进入下一个间隔（但不算“记得”）；不会天天追着同一道题问。想重来就说「c3 忘了」。

诚实边界：这些间隔是经验性的默认值，不承诺“按这个时间就一定记住”，也不知道你此刻是否真的快忘了。

> 不是今天讲完就忘：吱吱老师会在你**可能快忘**的时候，再问你一句。

这句话成立的前提：你同意了记录；“快忘”是按上面的经验间隔估计的，不是测量；自动提醒需要宿主定时器在运行，否则在你说「今天汇总」时出现。

## 两种复习模式

| | 定期复习（默认） | 每天复习 |
| --- | --- | --- |
| 出什么 | 只出到期点 | 昨天和过去 7 天的点每天问一次，直到你连续两次说「记得」；到期的旧点照常补上 |
| 数量 | 最多 3 个快问 | 最多 5 个快问 |
| 好处 | 省力，只在快到间隔时出现 | 习惯不断档 |
| 代价 | 要相信间隔，中间几天可能什么都不问 | 点一多容易累 |
| 怎么切 | 「改回定期复习」 | 「改成每天复习」 |

两种模式都只出一道快问，不把旧点重新讲一遍。

## DeepSeek Harness

本项目是 Harness bundle，包含两个插件行：

- `tech-companion`：静态行为指导，加到现有会话的系统提示里。不创建后台服务、不保存聊天记录、不触发额外模型调用。
- `tech-companion-ledger`：学习账本。注册 4 个工具（`tech_companion_card` / `_digest` / `_review` / `_settings`），读写本机的 `ledger.json`。它依赖 Harness 的工具注册表；没有工具注册表的 profile 里这一行不加载，静态指导照常工作。

安装到 CLI 的 profile（名字按你的安装来，例如 `web`、`tui`、`headless`）：

```sh
dsh plugin --profile web add github:jf143757-max/dsh-tech-companion
```

注意：独立 CLI（npm 上的 `@deepseek-ai/dsh` 0.2.1-rc.5）会拒绝 `--profile desktop`，提示该 profile 由 Electron 应用独占管理；Desktop 应用用户请通过应用自己的插件管理安装（本仓库没有在 Desktop 应用里验证过）。

新会话里可以这样试：先发一个任务，比如“我家是千兆宽带，帮我查一下为什么下载速度不到 1000 MB/s。”；看到默认套餐后回“好”；再说“今天汇总”。

定时：Harness 的定时任务（`schedule_create` 等工具）只在带定时服务的 profile 里有，例如 `web`；`headless` 没有。有的话，助手在你同意后创建一个名为“吱吱老师每日汇总”的每日提醒，投递到当前对话，你也能在 Automation tasks 页面看到、暂停或删除它。它只在 Harness 运行时触发；Harness 的定时器不能按条件跳过，所以空日你会看到这条触发消息和一句“今天没有新点，汇总跳过”。没有定时服务时，助手会直接说明，汇总在你说「今天汇总」时生成。

开和关：

- 不想记了：说「关闭记录」。不想定时发：说「暂停汇总」（助手会同步暂停定时任务），或在 Automation tasks 页面暂停。
- 只要提醒、不要账本：在 profile 的 `cordis.patch.yml`（`$DSH_HOME/profiles/<profile>/cordis.patch.yml`）里写：

  ```yaml
  - id: tech-companion-ledger
    disabled: true
  ```

- 换数据位置：设置 `TECH_COMPANION_HOME`，或给 `tech-companion-ledger` 行配置 `config: { home: /path }`。
- 卸载：

  ```sh
  dsh plugin --profile web remove dsh-tech-companion
  ```

具体 profile 名与启动方式取决于你的 Harness 安装；详见 [Harness 官方打包文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/docs/user/develop/basic/publish.md)和[定时提醒文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/docs/user/guide/schedule.md)。

## Hermes Agent

`skills/tech-companion/` 是一个 Hermes 技能文件夹：`SKILL.md` 里是和 Harness 完全相同的提醒指导（测试会逐字比对），加上一段用 `terminal` 工具调用账本脚本的说明。账本脚本需要本机有 Node.js 18+（Hermes 的安装器通常会带上 Node）。

安装：把整个文件夹放到 `~/.hermes/skills/` 下（复制或软链接都行）：

```sh
git clone https://github.com/jf143757-max/dsh-tech-companion
```

```sh
cp -r dsh-tech-companion/skills/tech-companion ~/.hermes/skills/
```

加载方式：

- 每次启动时预加载：`hermes -s tech-companion`，或单次提问 `hermes -s tech-companion chat -q '你的问题'`。
- 每个新会话都自动生效：在 `~/.hermes/config.yaml` 里配 `skills.auto_load: [tech-companion]`。**这个配置项只在较新的 Hermes 里有**；PyPI 上的 Hermes 0.19.0 没有它，配了也不生效（已实测），0.19.0 请用 `-s`（可以做成 shell alias）。
- 两者都不配时，Hermes 只在技能索引里列出这个技能的名字，由模型按需加载，不保证每次都用上。

定时：Hermes 技能自己不能唤醒对话，每日汇总要靠 Hermes 的 cron，而 cron 只在 gateway 运行时触发（`hermes gateway`）。

```sh
cp ~/.hermes/skills/tech-companion/scripts/hermes-cron-gate.sh ~/.hermes/scripts/tech-companion-gate.sh
```

```sh
hermes cron create "*/30 * * * *" "Present the tech_companion_digest from the script context as 吱吱老师今日汇总. Keep each new point's 知识点/为什么/任务场景/能这样说; give each review point exactly one quick question; if reviewQuestionIsTemplate is true, replace the 复盘小问题 with one question naming the real common thread of today's points." --script tech-companion-gate.sh --skill tech-companion --deliver origin --name tech-companion-digest
```

这个门控脚本每 30 分钟检查一次，但一天最多唤醒模型一次：到了设定时间、并且有新点或到期点才唤醒；否则输出 `{"wakeAgent": false}`，不调用模型、不发任何东西。所以改时间（「改成 22 点」）不需要改 cron。想完全不调用模型，可以改用 `hermes-cron-text.sh` 配 `--no-agent`，直接把汇总文字发出去（复盘小问题是模板题）。

渠道的诚实说明：在消息平台（如 Telegram）里创建的任务，`origin` 就是这个聊天；在 CLI 里创建的任务没有可以回投的聊天，汇总只会写到本地文件 `~/.hermes/cron/output/`（已在 0.19.0 实测），不会出现在对话里。关掉：`hermes cron pause tech-companion-digest` 或 `hermes cron remove tech-companion-digest`，或者说「暂停汇总」（门控随即保持安静）。

详见 [Hermes 技能文档](https://hermes-agent.nousresearch.com/docs/guides/work-with-skills/)、[自动加载说明](https://hermes-agent.nousresearch.com/docs/user-guide/cli)和 [cron 文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)。

## 做不到的事

- 静态指导不能定时推送、不能记账、不能保证模型每次照做；遇到不确定的问题仍应核对事实。
- 自动每日汇总依赖宿主定时器：Harness 要在带定时服务的 profile 里、由助手在你同意后创建，并且 Harness 在运行；Hermes 要配 cron 并运行 gateway。
- 间隔是经验启发式，不测量记忆，不承诺记住。
- 账本是单个本地文件；多个会话同时写时，后写的会覆盖先写的那次改动。
